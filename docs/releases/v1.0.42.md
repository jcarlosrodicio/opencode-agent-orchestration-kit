# v1.0.42 - Safe lifecycle and canonical release identity

This patch release makes the package easier to find, evaluate, and install as
an open-source multi-agent orchestration harness for OpenCode. It clarifies the
bounded-autonomy model and public safety guarantees without changing runtime
behavior.

## Highlights

- Clarify OAK's category, engineering workflow, bounded autonomous execution,
  and intended audience in the README and command documentation.
- Add a factual comparison of prominent OpenCode orchestration approaches,
  including the tradeoffs that distinguish OAK.
- Add npm and GitHub discovery metadata plus direct published-package install
  instructions for the `oak` and `oc-switch` CLIs.
- Add a repository-ready Awesome OpenCode submission draft.
- Document the repository's validation and supply-chain quality signals.

## Installation or upgrade

Install or upgrade the published CLI package:

```bash
npm install --global opencode-agent-orchestration-kit@1.0.42
oak version
oak install --dry-run
oak install
```

The npm installation exposes the CLIs but does not mutate OpenCode
configuration. `oak install` remains a separate, explicit operation.

## Migration

No migration is required. This release changes public documentation and
package metadata only; existing harness configuration and runtime behavior
remain compatible.

## Validation performed

The full 1,068-test unit and script suite, contract check, type checking,
dependency vulnerability and signature audits, isolated installation smoke,
exact-package smoke, clean archive inspection, and release provenance checks
passed.

## Public safety boundary

The public release excludes private OpenCode and Pi configuration, local
providers and MCP wiring, credentials, authentication files, raw transcripts,
private evidence, absolute machine paths, and runtime state. Pi uses its own
native model catalog and is not included in this OpenCode package.
