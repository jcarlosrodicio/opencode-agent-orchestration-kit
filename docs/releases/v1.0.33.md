# v1.0.33 - Safe lifecycle and canonical release identity

This release completes Phase 3 with a more diagnosable, maintainable, and
auditable public kit while preserving its local-first and human-gated scope.

## Highlights

- `doctor.sh` now reports twelve ordered, actionable checks covering runtime,
  compatibility, dependencies, managed-file drift, configuration, optional
  plugins, executable permissions, the skill registry, and stale state.
- The dependency-free `oak` CLI exposes the existing install, upgrade, doctor,
  check, replay, uninstall, rollback, and version engines through one closed
  command surface without adding a second implementation.
- A closed declarative contract cross-checks public agents, permissions,
  delegations, commands, workflows, retries, completion authority, and evidence
  against the shipped frontmatter and routing corpus.
- The formal threat model records actors, assets, trust boundaries, agent
  capabilities, twenty risks, and exact coverage of the eleven adversarial
  scenarios.
- Two dependency-free reproducible case packs compare harness and reduced
  flows. Their four live observations are published honestly as failures under
  exact repository equivalence; no successful benchmark claim is inferred.
- The supply-chain contract pins `brace-expansion` 5.0.8 to remediate
  GHSA-mh99-v99m-4gvg in the transitive OpenTUI/Babel dependency path without
  accepting the audit tool's incompatible downgrade.

## Installation or upgrade

For a new installation, preview the complete ownership plan before applying it:

```bash
./install.sh --dry-run
./install.sh
```

For an existing manifest-owned installation, preview and apply the upgrade:

```bash
./upgrade.sh --dry-run
./upgrade.sh
./doctor.sh
```

The supported runtime contract remains Node.js `^22.9.0 || ^24.0.0` with
OpenCode `>=1.14.41 <2.0.0`.

## Migration

No ownership-manifest schema or private configuration migration is required.
The new CLI, contracts, threat model, and case packs are additive. Existing
managed installations should use the normal dry-run upgrade flow so ownership
and preserved configuration remain explicit.

## Validation performed

Release readiness covers contract checks, 968 bundled script tests,
typechecking, zero-vulnerability production audit, 128 verified registry
signatures, 29 verified attestations, installation smoke, package smoke,
canonical version/tag validation, public leak scanning, and package-content
inspection.

The four use-case observations consumed one invocation per variant with no
retries. Raw output, temporary repositories, model/provider identity, and
reliable aggregate token totals were not published.

## Public safety boundary

The public release excludes private OpenCode configuration, local provider and
MCP wiring, credentials, authentication files, raw transcripts, private
evidence, user-specific absolute paths, machine-local state, and private
specification or planning documents. Local provider, search, and MCP
integrations are not part of this release.
