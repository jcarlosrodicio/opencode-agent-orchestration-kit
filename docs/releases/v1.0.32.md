# v1.0.32 - Safe lifecycle and canonical release identity

This release adds crash-recoverable state for bounded `/loop` workflows and a
portable adversarial suite that exercises the kit's real safety boundaries.

## Highlights

- `/loop` now keeps a schema-v1 JSON snapshot, append-only JSONL history, and an
  exclusive lease alongside the approved human-readable contract.
- Contract hashing prevents a changed task from reusing prior approval, while
  idempotent action IDs and explicit repair recover interrupted transitions.
- State paths reject traversal and symlink escapes, and same-session
  transitions are serialized by a dedicated transition lock.
- A portable corpus covers 11 adversarial threats: injection in diffs and
  repository documentation, unsafe symlinks and paths, control-character
  filenames, shell-wrapper bypass, review-network exfiltration, approval
  manipulation, credential canaries, unpinned external references, and corrupt
  or repeated events.
- The adversarial tests exercise existing review, permission, loop-state,
  replay, sanitization, and supply-chain controls rather than introducing a
  separate security engine.
- Orchestrated reviewers have no network access, general review network access
  requires approval, and wrapper arguments cannot silently broaden shell
  allowlists.

## Installation or upgrade

For a new installation, preview the complete ownership plan before applying it:

```bash
./install.sh --dry-run
./install.sh
```

For an existing manifest-owned installation, preview and apply the upgrade:

```bash
./upgrade.sh --dry-run
./upgrade.sh
./doctor.sh
```

The supported runtime contract remains Node.js `^22.9.0 || ^24.0.0` with
OpenCode `>=1.14.41 <2.0.0`.

## Migration

No ownership-manifest or configuration migration is required. Existing loop
contracts remain the human-readable source of approval; structured state is
created or migrated only through the explicit loop-state commands.

## Validation performed

Release readiness covers contract checks, 856 bundled script tests,
typechecking, dependency and signature audits, installation smoke, package
smoke, canonical version/tag validation, public leak scanning, and independent
review of the private/public port.

The adversarial corpus uses symbolic canaries only. It performs no model calls,
network requests, plugin installation, or private-provider access.

## Public safety boundary

The public release excludes private OpenCode configuration, local provider and
MCP wiring, credentials, authentication files, raw transcripts, private
evidence, user-specific absolute paths, machine-local state, and private
specification or planning documents. Local provider, search, and MCP
integrations are not part of this release.
