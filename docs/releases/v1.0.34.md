# v1.0.34 - Safe lifecycle and canonical release identity

This release adds a bounded local `/autonomous` workflow to the portable
OpenCode harness. It remains local-first and does not grant publication,
network, worktree, or scheduling authority.

## Highlights

- `/autonomous` runs an explicitly invoked local task through a finite
  `developer -> reviewer -> developer (state sync)` cycle of at most six
  iterations.
- The packaged `oak state` runtime records durable state, an append-only
  history, and a lease under the target checkout's `.opencode/loops/` path.
- Completion requires a contract-bound `APPROVE` attestation from a `reviewer`
  subagent. A developer cannot self-approve or mark the task completed without
  that evidence.
- `oak state` exposes initialization, resume, action recording, inspection,
  repair, migration, release, and reviewer-attestation operations through the
  installed CLI.

## Installation or upgrade

For a new installation, preview the complete ownership plan before applying it:

```bash
./install.sh --dry-run
./install.sh
```

For an existing manifest-owned installation, preview and apply the upgrade:

```bash
./upgrade.sh --dry-run
./upgrade.sh
./doctor.sh
```

The supported runtime contract remains Node.js `^22.9.0 || ^24.0.0` with
OpenCode `>=1.14.41 <2.0.0`.

## Migration

No ownership-manifest schema or private configuration migration is required.
The `/autonomous` command and durable state CLI are additive. Existing managed
installations should use the normal dry-run upgrade flow so ownership and
preserved configuration remain explicit.

## Validation performed

Validation covers the public contract check, 122 harness contract tests, 29
durable-state and CLI tests, version/tag validation, and public leak scanning.

## Public safety boundary

The public release excludes private OpenCode configuration, local provider and
MCP wiring, credentials, authentication files, raw transcripts, private
evidence, user-specific absolute paths, machine-local state, and private
specification or planning documents. Local provider, search, and MCP
integrations are not part of this release.
