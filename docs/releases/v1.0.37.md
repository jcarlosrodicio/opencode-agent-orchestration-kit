# v1.0.37 - Safe lifecycle and canonical release identity

This patch release adds a public shell export guard that blocks high-signal
environment enumeration and secret propagation while preserving ordinary setup
exports such as `PATH` and `NODE_ENV`.

## Highlights

- Shell assignments are classified before execution and sensitive export
  patterns are rejected by the public plugin.
- The policy is shared by the shell-export contract checker and its tests so
  the documented guard behavior remains deterministic.
- Public documentation and package checks describe the new safety boundary.

## Installation or upgrade

For a new installation, preview the complete ownership plan before applying it:

```bash
./install.sh --dry-run
./install.sh
```

For an existing manifest-owned installation, preview and apply the upgrade:

```bash
./upgrade.sh --dry-run
./upgrade.sh
./doctor.sh
```

The supported runtime contract remains Node.js `^22.9.0 || ^24.0.0` with
OpenCode `>=1.14.41 <2.0.0`.

## Migration

No migration is required. Existing installations can be upgraded using the
normal manifest-owned upgrade flow.

## Validation performed

Release readiness covers the public contract checks, unit and script tests,
type checking, dependency and signature audits, installation smoke, package
smoke, canonical version/tag validation, and the CI matrix for supported Node
and OpenCode compatibility versions.

## Public safety boundary

The public release excludes private OpenCode configuration, local provider and
MCP wiring, credentials, authentication files, raw transcripts, private
evidence, user-specific absolute paths, machine-local state, and private
specification or planning documents. Local provider, search, and MCP
integrations are not part of this release.
