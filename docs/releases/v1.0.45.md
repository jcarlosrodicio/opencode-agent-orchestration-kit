# v1.0.45 - Safe lifecycle and canonical release identity

This patch release makes `lead` a router in fact and not only in its contract.
Its `bash` permission defaulted to `ask`, and with `--auto` OpenCode
auto-approves every permission that is not explicitly denied, so `lead` could
run any command, writes included, and it implemented changes itself instead of
delegating them. It also states the routing decision as fields instead of
prose, and it stops the package from shipping files that git does not track.

v1.0.44 is deprecated: its tarball included `docker/open-design/data/` and
`docker/open-design/opencode-auth/`, local runtime state of the Open Design
container that is git-ignored but was matched by `files`. Both databases were
empty - no sessions, messages, accounts or tokens - and no credential, private
path or private endpoint was found in them or in the two container logs, but
they were never meant to be public. Upgrade to v1.0.45.

## Highlights

- `lead` cannot implement. `bash` now defaults to `"*": deny`, with the
  read-only allowlist and the exact scripts lead's own commands tell it to run
  (`loop-state.mjs inspect` for `/loop`, `preflight-audit.mjs` for `/evolve`).
  The contract states the rule: `lead` always delegates, and a one-line change
  is no exception. Measured after the fix, `lead` delegated to `developer` and
  `reviewer` in every run and implemented nothing itself.
- `lead` routes in fields, not prose: `route`, `confidence`, `skipped` and a
  one-line `why` only when confidence is low. Justifying discarded agents is
  forbidden; measured, the routing turn generated up to 13,116 output tokens,
  much of it explaining why agents that obviously did not apply were skipped.
- `opencode/scripts/check-harness.mjs` pins both. The permission check reads
  only the `bash:` block, because `task` also defaults to `"*": deny` and a
  whole-frontmatter match would have let an `ask` pass.
- The package ships only files that git tracks. `package-smoke` compares the
  tarball listing with `git ls-files` and refuses any other file before
  extraction, because npm packs whatever `files` matches on disk, ignored
  local state included, and a denylist of names cannot anticipate the next
  local file. `files` also excludes the Open Design container's runtime
  directories, and the supply-chain contract pins that list.

## Installation or upgrade

Install or upgrade the published CLI package:

```bash
npm install --global opencode-agent-orchestration-kit@1.0.45
oak version
oak install --dry-run
oak install
```

The npm installation exposes the CLIs but does not mutate OpenCode
configuration. `oak install` remains a separate, explicit operation.

## Migration

No migration is required. Existing harness configuration remains compatible.
A `lead` that used to be approved to run arbitrary commands under `--auto` is
now refused them and delegates instead; a local command that relies on `lead`
running a script outside the allowlist needs that exact command allowlisted,
not a broader default.

## Validation performed

The public contract check, unit and script suite, tag/version identity check,
`git diff --check`, and package smoke passed, the smoke now including the
tracked-files check against the exact tarball. GitHub Actions Check was green
on every merged pull request before the release tag.

## Public safety boundary

The public release excludes private OpenCode and Pi configuration, local
providers and MCP wiring, credentials, authentication files, provider URLs,
raw transcripts, private evidence, absolute machine-local paths, and runtime
state. The session measurements behind these changes stayed private: no model
names, session identifiers, or local database paths reached this repository.

Boundary statement: no private config, no credentials, no provider URLs, no
raw transcripts, no machine-local paths.
