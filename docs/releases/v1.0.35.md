# v1.0.35 - Safe lifecycle and canonical release identity

This release gives every review entry point one language- and
framework-neutral quality policy while preserving the kit's local-first,
read-only review boundary.

## Highlights

- The general reviewer now checks the real diff, task contract, original
  evidence, correctness, security, contracts, architecture, maintainability,
  tests, and residual risk before issuing a final verdict.
- Generic backend and frontend profiles adapt the policy to the changed
  surface. Strict Clean Architecture, DDD, hexagonal, CQRS, or layered profiles
  activate only when the task or repository explicitly declares them.
- Only defects introduced or materially worsened by the current task may block
  it. Relevant pre-existing debt is reported as a non-blocking observation.
- Review stages are explicit: deterministic preparation is `preflight`, focused
  specialist analysis is `partial`, and only the general reviewer may emit a
  `final` verdict.
- Operational Markdown such as agent, command, and skill contracts is no longer
  skipped as ordinary documentation during deterministic review preparation.

## Installation or upgrade

For a new installation, preview the complete ownership plan before applying it:

```bash
./install.sh --dry-run
./install.sh
```

For an existing manifest-owned installation, preview and apply the upgrade:

```bash
./upgrade.sh --dry-run
./upgrade.sh
./doctor.sh
```

The supported runtime contract remains Node.js `^22.9.0 || ^24.0.0` with
OpenCode `>=1.14.41 <2.0.0`.

## Migration

No ownership-manifest schema or private configuration migration is required.
The policy, profiles, review envelopes, and preparer classification are additive
to the normal ownership-safe upgrade path.

## Validation performed

Release readiness covers the public contract checks, bundled negative checker
tests, orchestrated-review preparer tests, typechecking, production dependency
audit, dependency signature and attestation checks, installation smoke, package
smoke, canonical version/tag validation, and public leak scanning.

## Public safety boundary

The public release excludes private OpenCode configuration, local provider and
MCP wiring, credentials, authentication files, raw transcripts, private
evidence, user-specific absolute paths, machine-local state, and private
specification or planning documents. Local provider, search, and MCP
integrations are not part of this release.
