# v1.0.30 - Safe lifecycle and canonical release identity

This release adds deterministic and opt-in live routing replay to the public
OpenCode orchestration kit while preserving its existing installation,
upgrade, rollback, compatibility, and supply-chain guarantees.

## Highlights

- A synthetic 14-scenario routing corpus now validates roots, delegation,
  skills, writes, reviews, budgets, stop conditions, and evidence completeness.
- The deterministic replay runner emits stable `pass`, `fail`, or
  `inconclusive` reports and fails closed when evidence is incomplete.
- An opt-in live adapter runs in a disposable repository with a fixed portable
  runtime configuration, exact-root session collection, bounded process
  cleanup, and sanitized reports.
- Raw live output remains temporary by default. Explicit private retention uses
  restrictive permissions and never becomes part of the canonical report.
- Harness checks enforce fixture parity, deterministic/live separation,
  privacy boundaries, and the handoff boundary for future Slice 2.3 metrics.

## Installation or upgrade

For a new installation, preview the complete ownership plan before applying it:

```bash
./install.sh --dry-run
./install.sh
```

For an existing manifest-owned installation, preview and apply the upgrade:

```bash
./upgrade.sh --dry-run
./upgrade.sh
./doctor.sh
```

The supported runtime contract remains Node.js `^22.9.0 || ^24.0.0` with
OpenCode `>=1.14.41 <2.0.0`.

## Migration

No ownership-manifest or configuration migration is required. The new replay
commands and synthetic fixtures are additive. Live replay remains explicitly
opt-in and is not part of normal checks or CI.

## Validation performed

Release readiness includes 811 bundled tests, deterministic replay across all
14 synthetic scenarios, fake-process live-adapter coverage, exact-root
collector regression tests, package installation and SDK import smoke, and
private/public parity and leak scans.

The single approved real-model smoke returned an honest `inconclusive` report
with `operational_status: ok`; no raw output was retained and the source
worktree remained unchanged.

## Public safety boundary

The public release excludes private OpenCode configuration, local provider and
MCP wiring, credentials, authentication files, raw transcripts, private
evidence, user-specific absolute paths, machine-local state, and private
specification or planning documents. Local provider, search, and MCP
integrations are not part of this release.
