# v1.2.1 - Safe lifecycle and canonical release identity

This patch release makes `oc-switch` work with OpenCode 2, makes `/loop` and
`/loop-status` find their state runtime in any project, and clears new
advisories in the dependency audit.

## Highlights

- **`oc-switch` works with OpenCode 2.** OpenCode 2 removed the `--pure` and
  `--refresh` flags of `opencode models`, so `oc-switch` could not load any
  catalog and every provider showed as unavailable. It now detects the
  OpenCode major version and, on OpenCode 2, reads `opencode models`, which
  already lists only providers with credentials. OpenCode 1 keeps the
  previous commands.
- **Saved models apply on OpenCode 2.** OpenCode 2 runs prompts through a
  background service that keeps the environment it started with, so new
  models had no effect until a manual restart. Saving now runs
  `opencode service restart` with the new model variables. If the restart
  fails, the models stay saved and `oc-switch` prints a warning that tells you
  to run `opencode service restart` yourself.
- **`/loop` and `/loop-status` use the runtime in the OpenCode config
  directory.** They called `scripts/loop-state.mjs` and
  `scripts/mission-status.mjs` relative to the project, where those files do
  not exist, and agents improvised their own state writer. Both commands now
  resolve the scripts from
  `${OPENCODE_CONFIG_DIR:-${XDG_CONFIG_HOME:-$HOME/.config}/opencode}`, and a
  missing runtime stops the loop instead of being improvised. `lead` can now
  run `/loop-status`, which its default deny rule blocked.
- **Dependency audit.** Exact overrides clear new advisories in the shipped
  OpenCode tool dependencies: `effect` (GHSA-chp3-j5qr-2vfr), `glob`,
  `minimatch` and `seroval`. The OpenCode 2 typecheck lockfile also takes
  patched `ip-address`, `undici` and `http-cache-semantics` versions.
- **Release checks ignore a local CodeGraph index.** The public boundary scan
  no longer fails on a `.codegraph/` directory, which is never packaged.

## Installation or upgrade

Install or upgrade the published CLI package:

```bash
npm install --global opencode-agent-orchestration-kit@1.2.1
oak version
oak upgrade --dry-run
oak upgrade
```

The npm installation exposes the CLIs but does not mutate OpenCode
configuration. `oak install` and `oak upgrade` remain separate, explicit
operations. Run `oak upgrade` to get the new `/loop` and `/loop-status`
commands in your OpenCode configuration.

## Migration

No migration is required. Existing harness configuration remains compatible.
On OpenCode 2, if you changed models with an earlier `oc-switch`, run
`opencode service restart` once from a new shell so the service picks them up.

## Validation performed

The public contract check, unit and script suite, typechecks for OpenCode 1
and OpenCode 2, compatibility and supply-chain checks, installation smoke and
package smoke passed. `oc-switch` was also run against OpenCode 2.4.1: it
loaded the catalog, and after a save the restarted service ran prompts with
the saved provider instead of the one in the calling shell. GitHub
Actions Check was green on the merged pull request before the release tag.

## Public safety boundary

The public release excludes private OpenCode and Pi configuration, local
providers and MCP wiring, credentials, authentication files, provider URLs,
raw transcripts, private evidence, absolute machine-local paths, and runtime
state.

Boundary statement: no private config, no credentials, no provider URLs, no
raw transcripts, no machine-local paths.
