# v1.0.31 - Safe lifecycle and canonical release identity

This release adds deterministic routing metrics over sanitized replay reports
while preserving the kit's installation, upgrade, rollback, compatibility, and
supply-chain guarantees.

## Highlights

- A new metrics aggregator consumes one or more Slice 2.2 replay reports only
  when `operational_status` is `ok` and their corpus digest matches.
- Routing accuracy, forbidden-agent activation, premature writes, review
  bypass, resume success, explicit human intervention, validation-failure
  closure, and delegations per accepted task are reported with numerators,
  denominators, values, and excluded inconclusive evidence.
- Zero-denominator metrics remain explicitly unavailable instead of being
  converted into invented zeroes.
- Token cost remains explicitly unavailable with `token-evidence-absent`
  because the v1 report contract contains no token-usage evidence.
- Reports are validated against a closed sanitized shape, including nested
  writes, reviews, limitations, and portable values. Diagnostics do not echo
  private input paths or unknown field names.
- The aggregator emits deterministic JSON and never calls a model, rereads raw
  evidence, or makes automatic harness-optimization decisions.

## Installation or upgrade

For a new installation, preview the complete ownership plan before applying it:

```bash
./install.sh --dry-run
./install.sh
```

For an existing manifest-owned installation, preview and apply the upgrade:

```bash
./upgrade.sh --dry-run
./upgrade.sh
./doctor.sh
```

The supported runtime contract remains Node.js `^22.9.0 || ^24.0.0` with
OpenCode `>=1.14.41 <2.0.0`.

## Migration

No ownership-manifest or configuration migration is required. The metrics
aggregator and its documentation are additive. Existing deterministic and
opt-in live replay commands keep their current interfaces.

## Validation performed

Release readiness covers contract checks, bundled script tests, typechecking,
dependency and signature audits, installation smoke, package smoke, canonical
version/tag validation, private/public production parity, and public leak
scans.

The canonical deterministic corpus remains a 14-scenario sanitized fixture set.
Inconclusive evidence is excluded from metric denominators rather than treated
as a pass or failure.

## Public safety boundary

The public release excludes private OpenCode configuration, local provider and
MCP wiring, credentials, authentication files, raw transcripts, private
evidence, user-specific absolute paths, machine-local state, and private
specification or planning documents. Local provider, search, and MCP
integrations are not part of this release.
