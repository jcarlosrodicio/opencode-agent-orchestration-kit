# v1.1.0 - Safe lifecycle and canonical release identity

This minor release replaces the Superpowers plugin with OAK's own process
skills, takes `/autonomous` all the way to an open pull request, and makes the
harness load on OpenCode 2 as well as OpenCode 1 from the same installation.
OpenCode 1 (`>=1.14.41 <2.0.0`) remains the supported line; OpenCode 2
(`>=2.0.18 <3.0.0`) is supported experimentally.

## Highlights

- **No external plugins.** Superpowers is removed. The starter `opencode.json`
  declares no `plugin` key, and the supply-chain, compatibility and smoke
  checks require that.
- **First-party process skills,** wired into the agents that own each phase:
  `oak-enrich-task` (lead, scoper, specifier), `oak-adversarial-review`
  (reviewer), `oak-runtime-verification`, `oak-update-docs` and `oak-commit`
  (developer). The `oak-` prefix keeps them from colliding with same-named
  skills in global skill directories.
- **`/autonomous` ends at an open pull request.** It enriches the task, opens a
  branch, plans, runs the loop, closes it and delivers through `oak deliver`,
  with a closed list of stop reasons. It never merges, deploys, releases or
  publishes.
- **`oak deliver pr|checks`** is the only push and pull-request path. It
  refuses unless the loop is completed with a matching reviewer attestation,
  the branch is not the default branch, the tree is clean and the branch is
  ahead of its base. It never force-pushes and has no merge action.
- **`oak state attest-review`** is implemented: a loop cannot record
  `completed` without a reviewer `APPROVE` bound to the approved contract.
- **`oak run`** keeps an optional task-run context. The mission runtime links
  each session to it, and `collect-session-evidence --run` tags execution
  trees with the run.
- **Developer git rules:** `developer` may branch, stage explicit paths and
  commit; bulk staging, hook bypass, push, `gh`, merge, `reset --hard` and
  branch deletion are denied.
- **OpenCode 2 (experimental).** Every plugin entry serves both runtimes. On
  OpenCode 2 the shell export guard, the `open_design_*` tools, the task-run
  session links, the token sidebar and the mission toasts all work. The
  session evidence collector reads OpenCode 2 databases, and `oak doctor`
  reports `info` for an OpenCode 2 release inside the experimental range.
  OpenCode-1-only code is isolated so it can be deleted when OpenCode 1 is
  retired; see `docs/opencode-v2.md`.
- **Smokes that prove plugins load.** The OpenCode 1 default smoke now imports
  every plugin file with the Bun runtime embedded in the OpenCode binary, and a
  new non-blocking OpenCode 2 workflow checks that every OAK plugin is active.

## Installation or upgrade

Install or upgrade the published CLI package:

```bash
npm install --global opencode-agent-orchestration-kit@1.1.0
oak version
oak install --dry-run
oak install
```

The npm installation exposes the CLIs but does not mutate OpenCode
configuration. `oak install` remains a separate, explicit operation.

## Migration

- Superpowers is no longer installed with the harness. If you relied on it
  outside OAK, install it yourself.
- The process skills are named `oak-*`. Custom prompts or local overrides that
  referenced the unprefixed names from the development branch must follow the
  rename.
- To try OpenCode 2, read `docs/opencode-v2.md` first. Both lines share the
  config directory and the database; going from OpenCode 1 to OpenCode 2 and
  back works, but OpenCode 1 cannot open a database that OpenCode 2 created
  from scratch.

## Validation performed

The public contract check, unit and script suite, typechecks for OpenCode 1
and OpenCode 2, compatibility, supply-chain and threat-model checks,
installation smoke and package smoke passed. Runtime smokes passed on OpenCode
1.14.41 and 1.18.4 (core and default) and on OpenCode 2.0.18 (core and
default) and `latest`. Manual sessions with a real model on OpenCode 1.18.4 and
2.0.18 are recorded in `docs/opencode-v2.md`. GitHub Actions Check was green on
every merged pull request before the release tag.

## Public safety boundary

The public release excludes private OpenCode and Pi configuration, local
providers and MCP wiring, credentials, authentication files, provider URLs,
raw transcripts, private evidence, absolute machine-local paths, and runtime
state. The session measurements behind these changes stayed private: no model
names, session identifiers, or local database paths reached this repository.

Boundary statement: no private config, no credentials, no provider URLs, no
raw transcripts, no machine-local paths.
