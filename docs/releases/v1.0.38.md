# v1.0.38 - Safe lifecycle and canonical release identity

This release adds a standalone OpenCode model switcher for quickly assigning
configured models to the default, small/title, and individual agent routes.

## Highlights

- `oc-switch` provides a bounded interactive TUI with search, refresh, multi-agent selection, and persistent model assignments.
- The catalog is read from the current OpenCode installation and is independent from Pi's model catalog.
- The public README and model-routing documentation describe installation and shell persistence behavior.

## Installation or upgrade

Install or upgrade the public kit using the normal manifest-owned flow:

```bash
./install.sh --dry-run
./install.sh
./upgrade.sh --dry-run
./upgrade.sh
```

After installation, run `oc-switch` from the checkout or global package. The
README and [model guide](../models.md) include both the local `npm run
oc-switch` path and the global `npm install --global` path, plus the keyboard
guide.

## Migration

No migration is required. Existing OpenCode model variables remain valid; the
switcher adds an interactive way to edit them.

## Validation performed

The public contract checker, unit and script tests, type checks, dependency
audits, signature checks, installation smoke, package smoke, and canonical
version/tag checks pass for this release.

## Public safety boundary

The public release excludes private OpenCode and Pi configuration, local
providers and MCP wiring, credentials, authentication files, raw transcripts,
private evidence, absolute machine paths, and runtime state. Pi uses its own
native model catalog and is not included in this OpenCode package.
